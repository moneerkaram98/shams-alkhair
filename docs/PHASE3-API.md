# Stage 3 API — authenticated routes

All responses with student data are `Cache-Control: no-store`. All mutations require authenticated same-origin requests and validated UUIDs. Academic data is stored in physically distinct schema-specific models. Requests take `scope` as `men|women|academy` and check role **AND** row ownership before accessing data. Do not pass arbitrary model/table names from the client.

| Method | Path | Main purpose |
|---|---|---|
| GET | `/api/family/students` | Children linked to parent / own student record |
| GET | `/api/family/student?scope=&studentId=` | Own student attendance, learning records, published reports, notifications and teachers |
| GET | `/api/family/preferences?scope=&studentId=` | Own notification preferences |
| PUT | `/api/family/preferences` | Guardian choices: weekly/monthly, inApp/email opt-in. Cannot bypass teacher approval |
| GET | `/api/family/messages?scope=&studentId=` | Messages to or from authenticated user in linked child's thread |
| POST | `/api/family/messages` | Family → assigned teacher; teacher/supervisor → linked guardian |
| GET | `/api/family/report?scope=&studentId=&reportId=` | Secure printable HTML report; browser can save PDF |
| GET | `/api/staff/progress?scope=&studentId=` | Assigned teacher / authorized supervisor's notes |
| POST | `/api/staff/progress` | Save assessment with group membership + teacher assignment checks |
| GET | `/api/staff/reports?scope=&studentId=` | Staff's report listing |
| POST | `/api/staff/reports` | Draft report by UTC weekly or monthly start date |
| POST | `/api/staff/reports/publish` | Publish draft with teacher comment; add opted-in notification/delivery |
| PUT | `/api/staff/report-approval` | Staff controls approval policy for linked guardians |
| GET | `/api/staff/family-contacts?scope=&studentId=` | Linked guardian user IDs for authorized teacher's contact selector |
| GET | `/api/jobs/reports` | Protected CRON_SECRET automation: generate due reports; send queued opted-in emails |

## Security acceptance requirements

- Parent A requesting unlinked Student B → HTTP 403, including HTML print route.
- Student login only own `Student.userId` and matching scoped STUDENT role.
- Teachers restricted to `TeacherAssignment` and active `Enrollment`; unauthorized group/child → 403.
- Admin requesting women data without supervisor-approved grant → 403 and scoped database role cannot read other schema.
- Report not `PUBLISHED` → parent HTML/portal cannot retrieve it.
- A published report cannot be regenerated by staff POST; concurrent publish uses conditional update.
- Repeated cron run will not create duplicate report for same period; deliveries unique by report+guardian+channel.
- Reporting email requires active guardian link, `email=true`, `emailOptInAt != null`, and verified sender/provider.
- WhatsApp is intentionally reserved, not implemented.
