# مدرسة شمس الخير — حزمة التحقق من التكامل v6.2

## ما تغير الآن

1. جرى تعديل `app/api/auth/login/route.ts` لجعل قفل الحساب بعد المحاولات الفاشلة يعمل داخل معاملة PostgreSQL واحدة، ويستخدم قفلًا استشاريًا مقيدًا بالبريد حتى لا تتجاوز المحاولات المتزامنة العداد. إنشاء جلسة الدخول وتصفير العداد يتمان داخل المعاملة ذاتها. يوجد اختبار بالمحاكاة لثلاثة سيناريوهات؛ ليس اختبارًا لقاعدة البيانات الحقيقية.
2. أُضيف `lib/runtime-db-config.ts`: يتحقق من وجود ثمانية حسابات تشغيل منفصلة عند الإنتاج، ويرفض إعادة استخدام حساب بين الأقسام، ويفحص `schema` في رابط الاتصال، ويمنع استخدام مستخدم PostgreSQL إداري أو تسريب رابط مالك المخطط إلى Runtime الإنتاج.
3. أُضيف `.github/workflows/integration.yml` و`scripts/ci-postgres-integration.sh` لاختبار PostgreSQL 17 تجريبية جديدة تمامًا، وPrisma Validation وSchema Push ثم قيود وصلاحيات SQL، وTypeScript Build، والواجهة البرمجية.
4. عُدلت استعلامات الأقفال الاستشارية في التسجيل والدخول لتُرجع عددًا صحيحًا بدل قيمة PostgreSQL من النوع `void` غير المدعومة مباشرة في نتائج Prisma `$queryRaw`.
5. أُضيف `scripts/ci-privacy-smoke.mjs` لاختبار أن مشرف الرجال لا يقرأ بيانات النساء والعكس، وأن المدير لا يقرأ بيانات النساء قبل الموافقة، وأن التصريح مؤقت قابل للإلغاء ويُبطل بعد سحبه.
6. تضمنت الحزمة أحد عشر اختبارًا جديدًا (3 للدخول و6 لإعدادات الاتصال و2 للتأكد من سلامة استعلامات أقفال PostgreSQL)، لتصبح النتيجة **78/78 اختبارًا أوليًا ناجحًا** في بيئة إعداد الملفات.

| الفحص | النتيجة |

## تفعيل الاختبارات الحقيقية

1. أنشئ مستودع GitHub خاصًا بالمشروع وحمّل إليه الملفات، ولا ترفع أي `.env` أو تسجيل صوتي أو ملف خاص.
2. ستظهر مهمة **Synthetic PostgreSQL Integration** في GitHub Actions، ويمكن تشغيلها من `Actions > Synthetic PostgreSQL Integration > Run workflow`. تعتمد على بيانات وهمية داخل PostgreSQL 17 مؤقتة، ولا تحتاج أسرار المدرسة أو أي بطاقة دفع.
3. سيختبر الإجراء: `Prisma validate`, `Prisma generate`, `Prisma db push` لقاعدة فارغة، ملفات SQL للقيود والصلاحيات، إثبات عزل الأقسام بـ12 فحصًا، `TypeScript`, `Next.js build`, ثم التسجيل والحجز والتواصل والحضور والتصريح للمدير عبر HTTP.
4. إن فشل أي اختبار، اعتبره عائقًا قبل النشر، وراجع السطر المحدد في سجل GitHub Actions. لا تعطل اختبارًا أمنيًا لتجاوز فشل.
5. **`prisma db push` على قاعدة فارغة في CI لا يُثبت صلاحية ترحيل قاعدة إنتاج موجودة.** سنحتاج إنشاء migrations مُراجعة وتجربة backup/restore على بيئة staging قبل تشغيل المدرسة.
6. بعد نجاح CI، نربط PostgreSQL تجريبية دائمة ومزود الاستضافة بحسابات DB مقيدة، وننشر المشروع نفسه (لا صفحات المعاينة الثابتة) على رابط staging محمي ببيانات وهمية فقط.

## أوامر التحقق دون شبكة على الكمبيوتر المحلي

```bash
npm run verify:offline
bash -n scripts/ci-postgres-integration.sh
node --check scripts/ci-privacy-smoke.mjs
```

هذه الأوامر تفحص الكود، **ولا تستبدل** البناء الفعلي أو فحوص قاعدة البيانات.

## موانع إطلاق حقيقية لا تزال مفتوحة

- قاعدة PostgreSQL تجريبية متصلة بإثبات GRANT/REVOKE وRLS حيث يلزم، ثم اختبارات E2E حقيقية.
- حزمة migrations إنتاج مُعتمدة، تدقيق التغييرات، النسخ الاحتياطي واستعادة عينة.
- حماية طلبات تسجيل الدخول والتسجيل بمحدد معدل موزع (Redis/WAF أو خدمة مكافئة) بدل Map محلية متعددة النسخ، ومراقبة إساءة الاستخدام.
- استكمال وسائل موافقة الوالدين والتحكم بالحذف والتخزين الآمن للصوت والفيديو، واختبار البنية تحت الأحمال.
- تفعيل الخدمات المدفوعة فقط بعد ضبط الميزانية والصلاحيات (Cloudflare Stream، البريد، WhatsApp Business، ASR).
- تطبيق Android وiOS لم يُنشأ بعد، ولا يعد جزءًا من نشر الموقع التجريبي.

**لا ترفع بيانات حقيقية للطلاب أو الطالبات إلى هذه النسخة حتى تنتهي اختبارات التشغيل والأمان.**
